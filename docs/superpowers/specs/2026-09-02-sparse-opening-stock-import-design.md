# 稀疏期初库存导入兼容设计

日期：2026-09-02
状态：已确认并进入实现

## 背景

原期初库存导入契约要求 81 条物品资料和 243 条“物品 × 三仓”完整组合。实际盘点完成后，用户删除了已无库存的仓库/物品组合，并明确要求以最终保存的《期初库存》工作表为唯一事实来源。系统不得重新推断或补回已删除的组合。

## 决策

- 五张工作表的名称、顺序和表头保持固定。
- `物品资料`接受模板容量内 1—81 条非空业务行；`期初库存`接受 1—243 条非空业务行。
- 完全空白的模板行不参与解析；只要任一权威列有值，该行仍进入解析并执行完整字段校验。
- 不再要求每个物品都与 `WH-01`、`WH-02`、`WH-03` 形成完整笛卡尔积。
- 同一“仓库编码 + 物料编号”组合仍必须唯一；超出模板容量的权威业务数据仍阻塞导入。
- 仓库白名单、物料编码/分类、权威列禁用公式、数量和单价精度与范围、正库存必填单价、零成本正库存必填备注、金额服务端重算和汇总溢出校验保持不变。
- 预览令牌、文件摘要、管理员身份、主数据快照、会计期间、一次性导入和原子事务保护保持不变。

## 当前工作簿处理

- 原文件不覆盖；从最终《期初库存》保留的行生成独立兼容副本。
- 物品资料只保留库存表实际引用的唯一物料编号，并从现有静态资料重建名称、分类、单位、规格和参考单价。
- 仓库名称、物品信息、批次号、金额和校验结果固化为值，避免依赖公式缓存。
- 用户已确认 `WH-03 + HJ0001` 数量 798 按零成本录入，备注为“按《期初库存》确认零成本”。
- 空白数量不会自动视为 0，也不会自动删除；必须由业务确认后才能形成无阻塞预览。

## 验证与上线

- 单元测试覆盖完整历史模板、稀疏非空行、缺失组合允许、重复组合拒绝和越界业务行拒绝。
- 运行期初导入相关单元/集成测试、API 类型检查和差异检查。
- 兼容副本使用项目实际解析器验证，并完成五表渲染及公式错误扫描。
- 代码经独立审查、CI 和 PR 合并后发布；生产上传先执行预览，只有零阻塞错误时才允许一次性提交。
