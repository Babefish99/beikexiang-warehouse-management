# 项目状态与发布交接文档设计

## 目标

提供一份面向项目负责人、运维和后续开发者的简洁交接文档，使读者无需通读历史记录即可了解当前发布版本、手机端状态、企业微信进度、已验证事实、风险与下一步。

## 文档关系

- 新交接文档：`docs/项目状态与发布交接.md`，作为日常阅读和验收的摘要。
- `PROJECT_STATUS.md` 继续是项目的完整事实入口，保留发布历史、验证证据与后续任务规则。
- 两份文档都只记录已验证事实；交接文档链接回 `PROJECT_STATUS.md`，不复制 Secret、密码、Token、私钥或环境变量值。

## 信息架构

交接文档依次包含：

1. 当前结论与版本标识：已部署的服务器 release、发布源提交、Push 状态和正式验收边界。
2. 已交付范围：桌面端、手机端入库/出库/查询/通知，以及手机端明确保留电脑处理的范围。
3. 生产运行与验证：备份、迁移、容器健康、Caddy/API 健康检查和本地完整验证结果。
4. 企业微信状态：已具备的代码与服务器配置保护、尚未完成的可信域名/IP、审批模板/回调和真实全链路验收。
5. 风险与待办：按优先级列出公网入口探测、生产主数据、企业微信、备份演练和重复批次错误契约。
6. 运维边界：唯一发布分支、禁止覆盖原开发工作区、禁止 Push 的当前约束、数据卷和无关服务器目录保护。

## 事实与安全规则

- 仅使用已确认的 `PROJECT_STATUS.md`、本次发布记录与本地 Git 状态。
- 将“服务器内部健康已验证”和“当前电脑的公网 HTTPS 请求被重置”分开陈述，不把前者扩展为公网验收通过。
- 不将企业微信代码入口等同于企业微信可用；必须明确真实全链路尚未验收。
- 不记录任何生产 Secret、数据库连接串、私钥、SSH 公钥、会话信息或环境变量实际值。

## 验收标准

- 读者可在一个屏幕内获得当前版本、部署状态、手机端和企业微信的明确结论。
- 每项待办都有明确的下一步，不使用“已上线”“已联通”等超出证据的表述。
- 交接文档与 `PROJECT_STATUS.md` 的 release、提交、未 Push、企业微信和公网验证状态一致。
- 本次只修改 Markdown 文档并通过 `git diff --check`。
