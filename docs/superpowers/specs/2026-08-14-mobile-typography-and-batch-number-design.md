# 手机端字阶与入库批次号设计

## 目标

让手机端继续使用仓库系统电脑端的深蓝、橙色、白卡片和细边框语言，纠正首页仓库选择控件的视觉重量，并让正常登记入库的批次号由系统按采购日期统一生成。

## 范围

- 手机首页仓库选择与“手机入库 / 实际出库”快捷操作使用相同的 14px 操作文字；保留 44px 最小触控高度。
- 在移动断点统一语义标题：一级标题 25px、二级标题 18px、三级标题 15px；正文 14px、辅助说明 13px。
- 采购日期内容左对齐，包括 WebKit 日期编辑区域；不改变其原生日期选择器。
- 正常登记入库移除手工批次号输入。用户填写采购日期后，系统在提交时生成全局当日序号，格式固定为 `YYYYMMDD-001`，同日后续登记依次为 `002`、`003`。
- 成功提示显示服务端实际分配的批次号；确认弹窗仅说明“按采购日期自动生成”，不显示可能因并发而失真的预测编号。

## 非范围

- 不改期初库存的批次录入、既有历史批次或出库批次选择。
- 不改生产部署、生产数据库、Secret、企业微信配置、Docker 或远程服务。
- `D:\桌面\固定资产` 当前没有可复用的前端源码；本次以现有仓库电脑端的设计 token 为唯一可执行基线。

## 编号与一致性

入库 API 不再接受客户端 `batchNo`。服务端以已经校验过的采购日期取 `YYYYMMDD` 前缀，读取该前缀的已有批次号，分配最大三位序号加一。内存存储同步生成；Prisma 存储在事务内生成，并只对自动批次的唯一约束冲突做有限重试，保证并发请求不会创建重复编号。接口响应返回实际 `batchNo`。

## 表现与无障碍

标题级别由共享 CSS 选择器而非按页面复制字号控制。仓库选择和快捷操作维持同一操作层级；输入控件仍保持 44px 触控高度。正常入库表单把原“批次号”位置替换为不可编辑的说明文本，避免误以为可填写。

## 验证

- 单元测试：同日 `001` / `002`、日期前缀与三位补零、无效日期拒绝。
- API/内存集成测试：客户端不传 batchNo 仍成功，响应和批次查询返回实际编号；保留期初库存的手工批次路径。
- Prisma 集成测试：可用数据库时验证自动编号与唯一冲突重试。
- Playwright：手机入库页没有批次输入、采购日期左对齐、完成提示含实际编号；首页仓库选择与快捷操作同为 14px，H1/H2/H3 递减；桌面入库仍为两列并显示系统批次说明。
