# 仓库系统固定资产视觉与检索能力设计规格

## 目标

在不改变现有库存、企业微信审批、实际出库、调拨、退库、盘点和月度结账规则的前提下，将固定资产系统的视觉框架和高频导航能力迁移到仓库系统，并增加按仓库查看库存与全局物品检索能力。

## 已确认的产品决策

- 顶部组织选择器改为仓库选择器，选项包含“全部仓库”和三个启用仓库。
- 选择“全部仓库”时显示三个仓库合计库存；选择单个仓库时显示该仓库库存、批次和流水。
- 标准物品库是集团统一主数据，不因为仓库筛选而重复或隐藏；仓库筛选作用于库存余额、批次和库存流水。
- 全局搜索支持物品编码、名称、规格、分类、企业微信选项 key、批次号和仓库；结果显示库存数量、金额、批次和所属仓库。
- 当前“物品位置”先使用仓库和批次表达；暂不新增货架、柜位等库位字段。
- 通知中心只服务管理员，展示待出库审批、低库存、月末盘点、月度结账和库存业务异常提醒。
- 低库存沿用现有规则：三个仓库合计低于物品统一设置的预警值才提醒。
- 只保留系统导出 Excel；第一阶段不新增 Excel 批量导入。
- 不增加资产照片、二维码建档、资产保管人/部门/房间、资产生命周期、回收站和删除恢复。
- 调拨沿用仓库规则：无需审批、一次完成，不增加固定资产的多级调拨审批和调拨接收确认。
- 企业微信负责登录；顶部显示实际登录人和角色，不在仓库系统中提供密码修改。
- 保留移动端菜单框架，但移动端只提供库存查询和必要的确认入口。

## 视觉设计

- 复用固定资产系统的侧边栏、顶部栏、页面标题、卡片、按钮、表格、表单、状态标签、弹窗、间距和响应式规则。
- 顶部左侧保留系统名称；加入仓库选择器和全局搜索；右侧加入通知中心、登录人头像/姓名/角色和用户菜单。
- 底部安全信息板采用固定资产系统的尺寸、内边距和视觉层级，文案改为仓库数据安全运行信息。
- 首页指标卡采用固定资产系统的“图标块 + 标签 + 大数值 + 辅助说明”结构，四项指标分别对应库存品类、待出库审批、本月入库、本月出库。
- 报表、台账和表单统一使用固定资产系统的字号层级；标签不换行，字段和表格内容保持统一左对齐。

## 交互与数据流

1. 应用启动后读取当前登录用户和启用仓库列表；仓库选择保存到浏览器本地，并作为当前页面上下文。
2. 切换仓库时刷新当前页面数据，不改变企业微信审批、出库和调拨的业务状态。
3. 全局搜索请求库存检索接口；点击结果进入库存台账或打开物品库存详情，显示选定范围内的仓库、批次、剩余数量、采购单价和金额。
4. 报表查询和导出均携带仓库范围；“全部仓库”不传单仓库筛选或传明确的 all 语义，由服务端统一聚合。
5. 通知中心读取当前管理员可见的提醒，通知本身不修改库存；“全部已读”只改变通知展示状态。

## 后端接口边界

- 扩展报表汇总、流水和导出接口，支持可选 `warehouseId`；不改变原有不带筛选参数时的结果。
- 增加只读库存检索接口，返回物品、仓库、批次、剩余数量、采购单价和金额，不返回不可见的管理数据。
- 复用现有仓库列表接口；财务访问报表时可以读取启用仓库选项，但不能修改仓库。
- 低库存和待办数量复用现有库存状态与审批状态，通知中心只提供聚合结果。

## 不纳入范围

- Prisma 全业务持久化迁移。
- 企业微信审批模板的重新配置。
- 资产照片、二维码、资产折旧、资产报废、回收站和跨公司组织架构。
- 货架/柜位级库位管理。

## 验收标准

- 顶部可在全部仓库与三个单仓之间切换；首页、库存台账、报表中心的库存数据随选择变化。
- 全局搜索能根据物品关键词返回仓库、批次、数量和金额，并能进入台账查看。
- 报表的统计期间和交易类型筛选保持单行，表单、表格和模块标题左对齐。
- 通知中心能展示管理员相关提醒，用户菜单能显示当前登录姓名和角色。
- 原有库存业务测试、企业微信审批测试、报表导出测试全部保持通过。
