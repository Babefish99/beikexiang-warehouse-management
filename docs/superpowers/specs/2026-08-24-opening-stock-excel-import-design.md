# 期初库存 Excel 预览与一次性事务导入设计

> 状态：已确认
>
> 日期：2026-08-24

## 1. 目标

为集团仓库管理系统增加固定格式 Excel 的期初库存导入能力，使管理员可以在电脑端完成：

1. 上传并预览校验《集团仓库期初数据导入模板.xlsx》；
2. 查看物品、三仓盘点、数量、金额、错误和提醒；
3. 记录线下共同复核的财务人员；
4. 将缺失物品档案和非零期初库存一次性、原子地写入数据库；
5. 在数据库约束、权限和审计层防止重复导入或绕过整批校验。

本功能只处理实盘确认后的期初数据，不导入历史出入库流水。

## 2. 已确认的产品决策

| 主题 | 决策 |
| --- | --- |
| 零库存 | `0` 表示已盘点；参与预览、校验和统计，但不创建零数量批次、余额、入库明细或流水。 |
| 空白库存 | 空白表示未盘点，是阻塞错误。 |
| 财务复核 | 管理员与财务在线下共同核对；管理员在导入页填写财务复核人并勾选确认，不新增系统内双人审批。 |
| 导入次数 | 同一环境仅允许一次正式期初导入；成功后再次提交被数据库约束和业务校验共同阻止。 |
| 差错处理 | 正式导入后的差错通过盘点调整处理，不重新导入或追加期初库存。 |
| 物品建档 | Excel 中缺失的标准物品与期初库存放在同一事务内创建；已有编码只校验，不静默覆盖。 |
| 分类 | 按物料编码前缀映射：`BJ=白酒`、`HJ=红酒`、`CY=茶饮`、`WP=其他物品`。 |
| 业务日期 | 盘点基准日期同时作为期初批次日期和库存流水业务日期，并决定会计期间；实际提交时间另行审计。 |
| 解析位置 | Excel 只在服务端解析；浏览器不解析、不执行工作簿公式。 |
| 预览方式 | 使用无状态双阶段流程：预览返回短时签名凭证，提交时重新上传同一文件并重新校验。 |
| 原文件 | 服务端不永久保存上传的 Excel，不修改本地模板或原始历史文件。 |

## 3. 范围与非目标

### 3.1 本次范围

- 电脑端一次性 Excel 导入页面；
- 管理员状态查询、预览和正式提交接口；
- 固定模板结构、主数据、盘点数据和数据库状态校验；
- 缺失物品建档；
- 一次性导入记录、数据库迁移和分类 seed 修正；
- 非零期初批次、余额、入库明细和库存流水的整批事务写入；
- 成功与失败审计；
- 单元、集成、Prisma 和浏览器端测试；
- 相关 README、项目状态和交接文档更新。

### 3.2 非目标

- 填写真实盘点数量、确认单价或财务复核人；
- 导入任何本地或生产数据库；
- 部署到生产环境；
- 修改生产 Secret、企业微信配置或角色名单；
- 保存上传文件、历史版本或导入暂存明细；
- 系统内财务审批流；
- 历史 Excel 流水批量导入；
- 导入成功后的反向删除、覆盖或重导。

## 4. 总体架构

采用“服务端无状态预览 + 提交时重新解析 + 数据库单事务”的实现。

```text
管理员选择 Excel
  -> POST /admin/opening-stock/import/preview
  -> 服务端限制文件大小、解析、重算、读取当前主数据
  -> 返回预览结果 + 绑定管理员和文件摘要的短时凭证

管理员填写财务复核人并确认
  -> POST /admin/opening-stock/import/commit（同一 Excel + 预览凭证）
  -> 验证管理员、凭证、文件摘要和有效期
  -> 重新解析、重新校验主数据/期间/一次性状态
  -> Serializable 事务写入物品、期初库存和导入记录
  -> 返回不可变的导入结果摘要
```

主要模块：

- `OpeningStockWorkbookParser`：解析固定模板并输出与数据库无关的规范化数据和文件级问题；
- `OpeningStockImportService`：组合工作簿校验、主数据校验、预览结果、提交前重校验和业务错误；
- `OpeningStockPreviewTokenService`：签发和验证短时预览凭证；
- `OpeningStockImportStore`：查询状态并执行一次性事务写入；
- 管理员路由：处理 multipart、认证上下文、响应码和审计；
- `OpeningStockPage`：上传、预览、确认、提交和完成状态。

## 5. 工作簿契约

### 5.1 文件级约束

- 只接受 `.xlsx`；不接受 `.xls`、`.xlsm`、CSV 或压缩包；
- 单文件上限为 5 MB，且每次请求只允许一个文件；
- 必须恰好包含以下五张工作表，名称和顺序固定：
  1. `填写说明`
  2. `仓库清单`
  3. `物品资料`
  4. `期初库存`
  5. `核对汇总`
- `物品资料`必须为 1 行表头加 81 行物品；
- `期初库存`必须为 1 行表头加 243 行盘点数据；
- 固定表头必须逐列匹配，不接受缺列、改名、乱序或额外业务列。

解析器不执行公式，也不把公式缓存结果当作业务真相。服务端只读取人工输入和稳定业务键，并重新计算全部派生字段。

### 5.2 盘点基准日期

- 权威来源为 `填写说明!B6`；
- 接受真实 Excel 日期单元格或严格的 `YYYY-MM-DD` 文本；
- 统一规范化为日期字符串，并在持久化时使用 `YYYY-MM-DDT00:00:00.000Z`；
- 所有批次号使用该日期重新生成；
- 预览按该日期只读检查会计期间；期间不存在时视为尚未关闭，不因预览而创建记录；
- 正式提交时检查该日期所属会计期间，已关闭则阻止导入。

模板设计文档中“后续导入只读取物品资料和期初库存”的表述需要修正为：导入额外读取 `填写说明!B6` 作为权威盘点基准日期，其他说明、仓库清单和核对汇总内容仍不作为写库数据源。

### 5.3 物品资料

服务端读取并规范化以下字段：

- `物料编号`：去除首尾空格、转为大写，必须唯一并匹配 `^(BJ|HJ|CY|WP)\d{4}$`；
- `物品名称`：去除首尾空格后必填；
- `类别`：用于异常提示，不作为数据库外键；数据库分类由编码前缀决定；
- `单位`：去除首尾空格后必填；
- `规格`：空白规范化为 `undefined`；
- `参考单价`：只用于预览提醒，不写入物品主数据；
- `数据状态`和`问题说明`：不直接信任，服务端按规则重新生成问题。

分类映射固定为：

| 前缀 | 系统分类代码 | 系统分类名称 |
| --- | --- | --- |
| `BJ` | `CATEGORY_BJ` | 白酒 |
| `HJ` | `CATEGORY_HJ` | 红酒 |
| `CY` | `CATEGORY_CY` | 茶饮 |
| `WP` | `CATEGORY_WP` | 其他物品 |

模板类别允许值用于提示：`BJ` 对应白酒、`HJ` 对应红酒、`CY` 可包含茶叶/陈皮、`WP` 可包含物品/烟。`WP0010` 当前类别“个”是阻塞错误，必须人工纠正。参考单价缺失和不同编码的同名物品是非阻塞提醒。

若数据库已有相同物料编号：

- 必须处于启用状态；
- 规范化后的名称、单位、规格和系统分类必须一致；
- 任一字段冲突都阻止整批导入；
- 导入流程不得静默更新已有物品。

数据库不存在的编码会在正式事务中创建。

### 5.4 期初库存

服务端从每行读取：

- `仓库编码`；
- `物料编号`；
- `实盘数量`；
- `确认单价`；
- `备注`。

仓库名称、物品名称、类别、单位、规格、批次号、金额、校验状态和错误说明均由服务端重新解析或计算。工作簿公式被修改、未重算或缺少缓存结果不会改变服务端业务判断。

校验规则：

- 243 行必须完整覆盖 81 个物品与 `WH-01`、`WH-02`、`WH-03` 的笛卡尔积；
- 每个“仓库编码 + 物料编号”组合必须恰好出现一次；
- 仓库必须存在、启用，并与已确认正式名称一致；
- 物料编号必须存在于本工作簿的物品资料中；
- 实盘数量必须明确填写为非负数，最多 4 位小数，并能安全写入 `Decimal(18,4)`；
- 数量大于 0 时确认单价必填、非负、最多 4 位小数，并能安全写入 `Decimal(18,4)`；
- 数量大于 0 且确认单价为 0 时，备注必须说明赠送或无成本原因；
- 正库存行的备注随对应入库明细持久化，以保留零成本原因；零库存行不写入备注或任何库存明细；
- 数量为 0 时确认单价允许为空；为空时预览规范化为 0，但该行不会写库；
- 批次号由服务端生成：`OPEN-YYYYMMDD-<去横线仓库编码>-<物料编号>`；
- 同一“仓库 + 物品 + 批次号”不得与请求内或数据库现有批次冲突；
- 每行金额由服务端使用高精度十进制计算为“数量 × 单价”，按现有库存规则保存为 2 位小数；规范化后的单行金额必须可写入 `Decimal(18,2)`；
- 预览和导入总数量/总金额必须汇总规范化后的逐行值，并分别可写入 `Decimal(18,4)`/`Decimal(18,2)`，确保与数据库摘要和明细完全一致。

### 5.5 错误与提醒

每个问题包含：

```ts
interface OpeningStockImportIssue {
  severity: "ERROR" | "WARNING";
  code: string;
  sheet?: string;
  row?: number;
  field?: string;
  message: string;
}
```

错误使用稳定机器码，至少覆盖：文件类型/大小、工作表结构、基准日期、物料编码、分类异常、重复物品、主数据冲突、仓库冲突、盘点组合缺失/重复、空白/负数数量、单价、零成本说明、批次冲突、会计期间、已有库存和已完成导入。

存在任意 `ERROR` 时 `canCommit=false`。`WARNING` 不阻止提交，但必须在页面中可见。

## 6. API 设计

所有接口继续受现有 `/admin` 认证和 `VIEW_ADMIN` 权限保护，仅管理员可访问。

### 6.1 查询状态

`GET /admin/opening-stock/import/status`

返回三种状态之一：

- `AVAILABLE`：没有正式导入记录且没有库存流水；
- `BLOCKED_BY_ACTIVITY`：没有正式导入记录，但已有库存流水，不能再初始化；
- `COMPLETED`：已有正式导入记录，同时返回不可变摘要。

### 6.2 预览

`POST /admin/opening-stock/import/preview`

multipart 字段：

- `file`：一个 `.xlsx` 文件。

成功解析后返回 HTTP 200：

```ts
interface OpeningStockImportPreview {
  canCommit: boolean;
  previewToken?: string;
  previewExpiresAt?: string;
  fileSha256: string;
  baselineDate?: string;
  summary: {
    itemCount: number;
    newItemCount: number;
    existingItemCount: number;
    inventoryRowCount: number;
    positiveRowCount: number;
    zeroRowCount: number;
    totalQuantity: string;
    totalAmount: string;
  };
  issues: OpeningStockImportIssue[];
  rows: Array<{
    sheetRow: number;
    warehouseCode: string;
    itemCode: string;
    itemName: string;
    batchNo: string;
    quantity: string;
    unitCost: string;
    amount: string;
    remark?: string;
    disposition: "IMPORT" | "SKIP_ZERO" | "INVALID";
  }>;
}
```

`INVALID` 仅用于在预览中保留并定位存在阻塞错误的盘点行；正式提交只会接收 `IMPORT` 行，`SKIP_ZERO` 和 `INVALID` 均不会进入写事务。

文件无法作为工作簿解析或超过安全限制时返回 400/413。能够解析但存在业务错误时仍返回 200 和完整问题列表。

只有 `canCommit=true` 时才签发预览凭证并返回 `previewExpiresAt`。凭证使用域隔离 HMAC，绑定管理员 ID、文件 SHA-256、签发时间和过期时间，默认有效期 30 分钟；凭证不包含业务明细。

### 6.3 正式提交

`POST /admin/opening-stock/import/commit`

multipart 字段：

- `file`：与预览相同的 `.xlsx`；
- `previewToken`：预览接口签发的短时凭证；
- `financeReviewer`：去除首尾空格后必填，最长 100 个字符；
- `confirmed`：必须为 `true`。

服务端必须按以下顺序处理：

1. 验证登录管理员、凭证签名和有效期；
2. 读取文件并计算 SHA-256；
3. 验证文件摘要与凭证一致；
4. 重新解析工作簿；
5. 重新读取主数据、导入状态和会计期间；
6. 任一校验失败即返回 409，不进入写事务；
7. 校验通过后执行一次性事务，成功返回 201。

正式结果包含导入编号、基准日期、管理员、财务复核人、物品总数、新建物品数、盘点总行数、实际写入的正库存行数、跳过零库存行数、总数量、总金额和提交时间。`inventoryRowCount` 始终表示已校验的盘点总行数（固定模板为 243），`positiveRowCount` 表示实际写入库存的行数，`zeroRowCount` 表示校验通过但跳过写库的零库存行数。

### 6.4 旧接口

现有单行 `POST /admin/opening-stock` 停止写入并返回 HTTP 410 及中文提示，引导使用固定 Excel 整批导入。这样可以避免旧客户端绕过一次性、完整性和共同复核规则。

## 7. 数据模型与事务

### 7.1 一次性导入记录

新增 `OpeningStockImport` 模型，建议字段：

```prisma
model OpeningStockImport {
  id                String   @id
  fileSha256        String
  sourceFileName    String
  baselineDate      DateTime
  operatorId        String
  financeReviewer   String
  itemCount         Int
  createdItemCount  Int
  inventoryRowCount Int
  positiveRowCount  Int
  zeroRowCount      Int
  totalQuantity     Decimal  @db.Decimal(18, 4)
  totalAmount       Decimal  @db.Decimal(18, 2)
  importedAt        DateTime @default(now())
}
```

正式导入使用固定主键（例如 `INITIAL_OPENING_STOCK`）。数据库主键约束是并发与重复导入的最终防线。记录只保存摘要和来源指纹，不保存原 Excel 或 243 行原始数据。

统计字段口径固定：`inventoryRowCount = positiveRowCount + zeroRowCount`；其中只有 `positiveRowCount` 对应批次、余额、入库明细和库存流水数量。

现有 `InboundLine` 增加可空 `remark String?`，仅保存实际写入的正库存行备注；不新建 243 行暂存表，也不保存零库存行或原始工作簿。

### 7.2 分类 seed

结构化 seed 调整为四条规范分类：

- 修正 `CATEGORY_BJ/BJ` 名称为“白酒”；
- 新增 `CATEGORY_HJ/HJ`，名称为“红酒”；
- 保留并规范 `CATEGORY_CY/CY` 为“茶饮”；
- 保留并规范 `CATEGORY_WP/WP` 为“其他物品”。

预览和提交要求这四条分类存在且编码、前缀和名称一致。缺失或冲突时返回阻塞错误，不在导入流程中静默改写分类。

### 7.3 Serializable 事务

正式提交使用一个 Prisma `Serializable` 事务：

1. 确认固定主键的一次性导入记录不存在，且库存流水总数为 0；
2. 读取或创建基准月份的会计期间，若为 `CLOSED` 则失败；
3. 读取并校验四条规范分类、仓库、已有物品和现有批次；
4. 创建固定主键的一次性导入记录，作为并发提交的数据库约束占位；
5. 校验已有物品并创建缺失物品；
6. 为每个存在正库存行的仓库创建一张来源为 `OPENING_STOCK` 的入库单；
7. 为每条正库存行创建采购批次、库存余额、入库明细和 `OPENING_BALANCE` 流水；
8. 提交事务。

导入记录、物品、订单、批次、余额、明细、流水和期间创建中的任一步失败，事务全部回滚。固定导入主键、批次唯一键和 Serializable 隔离共同处理并发提交。

内存持久化实现相同的“先完整校验和构建草稿、再一次提交”语义，供本地开发和快速测试使用。

## 8. 权限、凭证与审计

- 操作人只从 `request.adminUser` 读取，不接受客户端提交 `operatorId` 或管理员姓名；
- 财务复核人是人工核对记录，不授予权限，也不替代已认证操作者；
- 预览凭证使用已有服务端会话密钥进行域隔离签名，密钥不会写入日志、响应、审计或数据库；
- 凭证采用常量时间签名比较，绑定管理员与文件摘要，并设置 30 分钟过期；
- multipart 限制文件数、字段数、部件数和 5 MB 文件大小；
- Excel 解析只读取固定范围，不执行宏、公式、外部链接或嵌入对象；
- 文件名只保存清理后的基本名称，并限制保存长度；
- 不记录文件 Buffer、完整 81/243 行内容或预览凭证；
- 正式提交通过现有管理员审计包装器记录 `OPENING_STOCK_IMPORTED`，实体为 `OPENING_STOCK_IMPORT`；
- 成功审计只保存导入编号、文件摘要、基准日期、管理员、财务复核人和汇总统计；
- 失败审计保存稳定错误信息和安全请求摘要，不保存敏感字段或原始文件。

## 9. 页面设计

`OpeningStockPage` 改为状态驱动的一次性导入页面。

### 9.1 可导入状态

页面分为四个区域：

1. 固定模板说明和 `.xlsx` 文件选择；
2. 预览摘要卡片：日期、物品数、新建/已有物品数、正/零库存行、总数量、总金额；
3. 问题列表和 243 行规范化预览，可筛选错误、提醒、写入行和跳过行；
4. 正式确认区：财务复核人、共同复核勾选框和正式导入按钮。

正式按钮只在无错误、文件未变化、当前时间早于 `previewExpiresAt`、复核人非空且已勾选确认时启用。

### 9.2 失败状态

- 预览失败保留已选择文件；
- 正式提交失败保留文件、预览结果、复核人和勾选状态；
- 文件、数据库状态或期间改变时提示重新预览；
- 错误按工作表、Excel 行号和字段定位；
- 不使用模糊的“请求失败”覆盖服务端业务错误。

### 9.3 已完成或被业务阻止

- `COMPLETED`：隐藏上传和提交控件，展示不可变导入摘要及“后续差错请通过盘点调整处理”；
- `BLOCKED_BY_ACTIVITY`：展示已有库存业务导致无法初始化的原因，不挂载上传提交表单；
- 手机端继续使用现有 `<=820px` 桌面专属门禁，不挂载该页面或发起导入专属请求。

## 10. 错误处理与状态码

| 场景 | 响应 |
| --- | --- |
| 未登录/无管理员权限 | 401/403 |
| 非 multipart、无文件、错误扩展名、损坏工作簿 | 400 |
| 文件或请求部件超过限制 | 413 |
| 能解析但有模板/数据错误 | 预览 200，`canCommit=false` |
| 凭证无效、过期、管理员或文件不匹配 | 409 |
| 已有库存、已正式导入、关闭期间、提交时主数据变化 | 409 |
| 并发唯一冲突 | 映射为 409 的稳定业务错误 |
| 未知基础设施错误 | 500，并由现有错误处理器和安全日志处理 |

## 11. 测试策略

行为修改采用测试驱动开发，先让测试按预期原因失败，再完成最小实现。

### 11.1 单元测试

- 工作表名称、顺序、表头和固定行数；
- Excel 日期与严格文本日期规范化；
- 服务端忽略公式结果并重算批次、金额和状态；
- 物品编码、重复编码、必填字段、前缀分类和 `WP0010`；
- 空白、零、负数、小数精度、正库存缺单价、零成本缺说明；
- 81 × 3 组合缺失和重复；
- 预览凭证签发、过期、篡改、管理员不匹配和文件不匹配。

### 11.2 API 与应用集成测试

- 管理员可预览和提交，财务/申请人不可写；
- multipart 文件和部件限制；
- 业务错误返回结构化问题；
- 新物品和正库存写入，零库存跳过；
- 旧单行接口不再写入；
- 成功与失败审计不包含文件 Buffer、凭证或敏感字段。

### 11.3 Prisma 集成测试

- 缺失物品、三仓订单、批次、余额、明细、流水和导入摘要在一个事务内写入；
- 第二行或后续写入失败时，前序物品与库存全部回滚；
- 固定主键阻止第二次及并发导入；
- 已有任意库存流水阻止首次导入；
- 基准月份已关闭时不产生任何写入；
- 数据库重启后导入摘要和库存完整保留。

### 11.4 浏览器端测试

- 选择文件并展示预览摘要；
- 阻塞错误按行展示且提交按钮禁用；

- 正式提交失败保留用户输入；
- 成功后展示锁定摘要；
