# 全站中文与界面一致性聚焦修正设计

## 背景

仓库系统已经形成固定资产系统风格的共享页面标题、按钮、表单、弹窗和响应式规则，但全站审计仍发现少量用户可见的英文业务状态、技术化字段表述、未指定层级的按钮，以及反馈文字字号和语义不一致。当前上线前阶段需要先修复价值高、风险低的偏差，不在本批次进行全量样式重构。

## 目标

- 用户可见的库存业务状态统一显示中文，不直接展示服务端英文枚举。
- 用户可见字段使用业务化中文表述，保留 Excel 等必要产品名称以及业务编码、批次号等原始数据。
- 所有共享按钮明确采用主要、次要或危险层级。
- 成功提示、弹窗辅助文字和期初库存分区标题遵循现有字号层级。
- 表单成功和失败反馈具备一致的 `status` / `alert` 语义。

## 实施范围

### 中文状态与业务表述

新增一个前端库存状态显示函数，覆盖当前页面可能显示的待出库、已完成、部分出库、无法出库、已取消、待处理、已通过、已拒绝、已撤回和未知状态。调拨、退库以及桌面和移动出库流程只通过该函数展示状态；未知英文枚举不得原样暴露给用户。

将“服务端 ID”改为“业务编号”，将物品维护中的“企业微信选项 key”及对应搜索提示改为“企业微信选项标识”。这只调整用户界面文字，不修改 API 字段名和数据结构。

### 按钮层级

期初库存状态读取失败时的“重新加载”按钮使用共享次要按钮样式。页面专用的搜索、导航和图标按钮保留现有专用样式。

### 字号层级

- 成功反馈统一为 13px，与表单错误反馈一致。
- 物品弹窗辅助说明统一为 13px。
- 期初库存分区标题统一为 18px，分区辅助说明统一为 13px。
- 页面主标题、表单标签、输入框、表格和移动端触控字号保持现有已验证值。

### 反馈语义

异步提交或加载失败的用户反馈使用 `role="alert"`；成功完成反馈使用 `role="status"`。覆盖物品、仓库、调拨、退库、盘点、报表和桌面出库等当前遗漏页面，不改变提示内容或提交行为。

## 非目标

- 不把物品维护专用宽弹窗迁移到共享小弹窗组件。
- 不清理 `styles.css` 的全部历史重复声明，也不重建全量设计令牌。
- 不集中翻译后端所有历史英文错误；服务端错误治理另列后续任务。
- 不修改业务 API、数据库模型、权限、企业微信配置或生产环境。

## 测试策略

1. 单元测试先锁定已知库存状态的中文显示和未知状态的中文降级文案。
2. 管理员 E2E 覆盖调拨、退库、桌面出库页面不暴露英文状态枚举。
3. 移动出库 E2E 覆盖待办和完成结果使用中文状态与“业务编号”。
4. 主数据和期初库存 E2E 覆盖中文字段表述、次要按钮层级、反馈语义和计算字号。
5. 完成针对性测试后运行相关完整 E2E、类型检查、生产构建和 `git diff --check`。

## 风险控制

状态转换仅发生在显示边界，提交请求和服务端返回保持不变。CSS 只调整四个已有选择器的最终覆盖值，不改布局尺寸和断点。语义属性只影响可访问性树，不改变视觉和业务流程。
