# 本地开发免企业微信登录设计

## 目标

在 VPN 导致公网 IP 不固定、企业微信 API 无法稳定调用的本地开发阶段，提供一个可控的本地登录入口，使开发人员可以直接进入仓库管理后台进行功能开发和验证。

该入口只服务本地开发，不替代正式环境的企业微信登录，也不改变企业微信审批入口设计。

## 已确认的决策

- 本地免登录身份固定为“本地管理员”。
- 现有企业微信登录保留，默认行为不变。
- 免登录必须由明确的环境变量开关开启。
- 仅非生产环境允许开启。
- 仅允许来自回环地址的请求使用本地免登录，避免局域网其他设备直接获得管理员会话。
- 本地登录复用现有会话 Cookie、会话服务、权限模型和登录审计。
- 不把本地开发开关及任何真实企业微信凭据提交到版本库。

## 方案

### 配置

新增环境变量：

```text
LOCAL_AUTH_BYPASS=false
```

实际本地开发时，在被 `.gitignore` 忽略的 `.env` 中设置为 `true`。代码同时检查运行环境不是 `production`，即使误把开关带到生产配置也不会启用。

### 后端

新增本地登录路由，例如 `GET /auth/local`：

1. 检查本地免登录开关和非生产环境。
2. 检查请求来源为 `127.0.0.1`、`::1` 或 IPv4-mapped loopback 地址。
3. 创建固定身份：
   - `id`: `local-admin`
   - `weComUserId`: `local-admin`
   - `name`: `本地管理员`
   - `role`: `ADMIN`
4. 记录现有登录审计事件。
5. 写入现有 `warehouse_session` Cookie，并重定向到请求的本地页面。

未满足条件时，本地路由返回拒绝响应，不创建会话。

现有 `/auth/wecom/authorize` 响应增加本地登录入口信息，仅在本地免登录可用时返回；开关关闭时不向前端暴露本地入口。

### 前端

登录页继续展示“使用企业微信登录”。当后端返回本地登录入口时，额外展示“本地开发登录”按钮；正式环境或开关关闭时不显示该按钮。

本地登录成功后，沿用现有 `/auth/session` 和权限加载流程，因此管理页面无需增加特殊判断。

## 安全边界

- 默认关闭。
- 生产环境强制关闭。
- 非回环请求不能使用本地登录路由。
- 本地管理员身份只存在于开发配置，不写入数据库或企业微信。
- 企业微信凭据继续只从本地 `.env` 读取，不进入设计文档、测试数据或日志。

## 测试与验收

### 后端测试

- 开关关闭时，本地登录路由拒绝请求。
- 生产环境即使开关为 `true`，本地登录路由仍拒绝请求。
- 开关开启且请求来自回环地址时，创建管理员会话并返回重定向。
- 非回环请求不能创建本地管理员会话。
- 企业微信授权路由在开关关闭时仍返回原有企业微信授权地址。

### 前端测试

- 本地登录入口存在时显示“本地开发登录”。
- 本地登录入口不存在时不显示该按钮。

### 手工验收

1. 在本地 `.env` 设置 `LOCAL_AUTH_BYPASS=true` 并重启 API。
2. 打开 `http://127.0.0.1:5174`。
3. 点击“本地开发登录”。
4. 能进入管理后台并看到管理员功能。
5. 将开关改为 `false` 并重启 API，本地登录入口消失，企业微信登录入口仍保留。
