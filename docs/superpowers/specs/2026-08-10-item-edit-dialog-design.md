# 物品编辑弹窗与状态操作设计

## 目标

将标准物品库的编辑表单从列表页面内嵌区域改为弹窗，保持页面排版稳定；同时明确停用物品的启用入口，并移除编辑场景中不需要维护的分类字段。

## 范围

- 仅调整标准物品库页面的编辑交互。
- 新增物品表单保持现状，不删除其中的“分类前缀”和“分类”字段。
- 后端接口、权限模型、审计记录和数据结构不变。

## 交互设计

1. 点击列表中的“编辑”后，打开居中的编辑弹窗，列表页面不再插入编辑面板。
2. 弹窗保留编辑所需字段：编码、名称、规格、单位、企业微信选项 key、最低库存。
3. 编辑弹窗删除“分类前缀”和“分类”两个可见字段。
4. 保存时沿用当前物品已有的分类信息，隐藏字段不会被清空或改写。
5. 点击“取消”或关闭按钮关闭弹窗；保存成功后关闭弹窗并刷新列表。
6. 保存失败时弹窗保持打开，保留用户已填写的内容并显示错误提示。
7. 启用状态物品只显示“停用”按钮；停用状态物品只显示“启用”按钮。

## 实现方案

- 复用 `ItemsPage` 现有的 `editingItemId`、`editForm` 和 `submitEdit` 状态及提交逻辑。
- 将编辑表单移动到 modal overlay 容器中，并增加稳定的弹窗语义（`role="dialog"`、标题和关闭按钮）。
- `ItemFormState` 继续保留分类字段供 PATCH 请求使用，但编辑表单不渲染对应控件。
- 通过现有的 `activateItem` / `deactivateItem` API 调用维持状态切换和管理员审计。
- 使用现有按钮、表单和面板视觉变量，新增的弹窗样式仅包含遮罩、定位、尺寸和移动端适配。

## 验收标准

- 编辑按钮打开弹窗，页面列表上方没有新增编辑行或编辑面板。
- 弹窗内看不到“分类前缀”和“分类”字段，编码、名称、规格、单位、企业微信选项 key、最低库存均可编辑。
- 编辑保存成功后弹窗关闭，列表刷新并展示新值。
- 编辑接口失败时弹窗不关闭，输入值和错误提示保留。
- 停用物品可看到并点击“启用”；启用物品可看到并点击“停用”，不可同时显示两个状态按钮。
- 现有新增物品、管理员权限和审计相关测试继续通过。

## 非目标

- 不修改物品分类数据模型或后端 PATCH 请求格式。
- 不改变新增物品页面的字段。
- 不新增删除物品、批量状态切换或状态审批流程。
