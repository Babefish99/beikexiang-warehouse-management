## 已交付范围

### 电脑端

电脑端仍是完整操作端，保留库存台账、主数据、期初库存、入库、审批出库、调拨、退库、盘点、月结、报表和导出等能力。

### 手机端

手机端为现有 React 网页的响应式适配，不新增独立 App，已支持：

- 库存、物品、仓库和批次查询；
- 通知与待办查看；
- 单页登记入库；
- 四步实际出库与取消操作。

以下复杂操作在手机端明确提示“请在电脑端处理”，不挂载可写表单：物品库、仓库维护、期初库存、调拨、退库、盘点、月结。

### 本轮关键规则与界面收敛

- 正常登记入库时，选择采购日期后由服务端统一生成批次号，格式为 `YYYYMMDD-001`（例如 `20260814-001`）；手机端仅展示只读预览，不能手工填写。期初库存与历史批次仍保留原有手工批次规则。
- Prisma `ProcurementBatch` 唯一约束冲突在本地新实现中统一为 HTTP 409 和稳定消息 `batch number already exists`；自动批次仍最多重试 3 次，其他模型的唯一约束错误不会误报为批次重复。前端同时保留弹窗和表单草稿，在批次字段显示中文错误及 `aria-invalid`。
- 手机端采购日期、批次预览和采购人使用同规格的 44px 输入控件，日期文字左对齐；标题按一级 25px、二级 18px、三级 15px 递减。
- 首页仓库选择与快捷操作使用一致的 14px 字号并保留至少 44px 触控高度；出库空态图标与文字已成组对齐。
- 聚焦式 P1 修正统一了桌面/手机出库、调拨和退库状态的中文展示，手机“服务端 ID”改为“业务编号”，物品页技术字段改为“企业微信选项标识”；成功/错误反馈分别补充 `role="status"`/`role="alert"`，期初库存失败重试按钮使用既有次要按钮样式。该批次只做低风险收敛，不改变服务端状态、API、权限或数据库行为。
